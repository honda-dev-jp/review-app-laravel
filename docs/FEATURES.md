# 機能一覧

## このドキュメントの目的

このドキュメントでは、映画レビューアプリ Laravel移植版でMVPごとに実装・整備する機能と基盤をロードマップとして整理する。

MVP2の最新スコープ・優先順位・進捗は、GitHub Milestone「MVP2 - 初回公開版（v1.0.0）」と所属Issue / Pull Requestを正本とする。この文書ではIssue番号、Open / Closed状態、完了日を逐次管理せず、機能・項目の位置付けだけを扱う。

画面遷移、ルート、DB、セキュリティ、テスト運用等の詳細は、各正本文書を参照する。

## MVP1 - 初期移植版

### アプリ機能

| 機能・項目 | 概要 |
|---|---|
| 作品一覧表示 | 登録済み作品を一覧表示し、ページネーション、平均評価、評価件数を表示する |
| 作品詳細表示 | 作品情報、レビュー、レビュー返信、平均評価、評価件数を表示する |
| 会員登録・ログイン・ログアウト | Laravel Breezeをベースに認証機能を提供する |
| パスワードリセット | Laravel Breeze標準のパスワードリセット機能を使用する |
| アカウント管理 | ユーザー名、プロフィール、パスワードを更新する |
| ユーザーアイコン | アイコンの登録・差し替え・表示と保存前プレビューを行う |
| レビュー・評価投稿 | 会員が作品にレビュー本文と評価を投稿する |
| レビュー削除 | 自分が投稿したレビューを削除する |
| レビュー返信 | レビュー返信の表示と投稿を行う |
| 本人レビュー一覧 | 自分のレビューをページ単位で表示する |
| 会員退会 | アカウントを削除し、既存のレビュー・返信は匿名表示で維持する |

| 機能・項目 | 概要 |
|---|---|

## MVP2 - 初回公開版（v1.0.0）

### 実装済み

#### アプリ機能

| 機能・項目 | 概要 |
|---|---|
| Laravel Breeze標準メール認証 | Laravel標準のメール認証によりメールアドレスを確認する |
| 認証メール再送 | 未認証ユーザーが認証メールを再送する |
| 管理者認証・認可 | 既存のLaravel Breeze認証を維持し、`users.role`により管理者画面へのアクセスを制御する |
| 管理画面ダッシュボード | 管理者画面の基本構成と操作導線を表示する |

#### TMDB連携

| 機能・項目 | 概要 |
|---|---|
| TMDB API技術調査・検証（映画検索・ジャンル取得） | Movie Search、Configuration、Genre Movie Listの取得・変換・障害時処理を公式資料に基づいて設計・検証した |
| TMDB API連携・映画検索 | 管理者がTMDBの映画を検索し、ポスター付きの結果を最大5件、同一画面へ非同期表示する。No Imageやエラー時の表示を含む（Issue 212、PR 229で`develop`へ統合済み） |
| TMDB複数ジャンル取得 | 映画ごとの複数ジャンルID・日本語名称を取得し、順序を維持して検索結果JSONの`genres`へ追加する（Issue 231、PR 233で`develop`へ統合済み） |
| TMDB検索結果カード表示改善 | TMDBジャンルを参考表示し、カードの概要のみ100書記素クラスタで省略する。画像112×176pxの表示・欠損時のフォールバック等を確認済み（Issue 232、PR 234で`develop`へ統合済み） |

検索結果JSONの`overview`は全文を維持し、カードでの省略は表示処理だけで行う。ジャンルはアプリ独自カテゴリーの自動選択に使用しない。詳細は[TMDB映画検索技術設計](TMDB_SEARCH_DESIGN.md)を参照する。

#### TMDB連携（Issue 230：作業ブランチで実装済み・PR前）

| 機能・項目 | 概要 |
|---|---|
| 作品登録前の確認・編集モーダル | 検索結果カード全面のクリック・タップ・Enter・Spaceから、同一画面のネイティブ`<dialog>`を開く。TMDB ID・原題・公開日・ポスター・複数ジャンルは参照専用、タイトル・概要全文は編集可能とし、アプリ独自の固定12カテゴリーから1件を手動選択する（Issue 230） |
| 登録前モーダルの操作・アクセシビリティ | ×・キャンセル・Escapeで終了し、編集内容を破棄する。モーダル表示中の背景操作抑止、Tab／Shift+Tab、フォーカス復帰、ARIAに対応。登録ボタンは無効のまま、DB保存・登録API呼び出しは行わない（Issue 230） |

**進捗の区別**：上記2項目は`feat/230-tmdb-registration-modal`の作業ブランチで実装・ローカル検証済み（2026-11-01時点）。**`develop`への統合・PRマージは未実施**であり、前表のIssue 212・231・232の統合済み機能とは区別する。Playwright E2Eは全37件PASSの報告があるが、最終PRレビュー・CI結果の保証を意味しない。

#### 開発基盤

| 機能・項目 | 概要 |

| Laravel 13への更新 | Laravel 10からサポート対象版へ段階的に更新した |

#### アプリ機能

| 機能・項目 | 概要 |
|---|---|
| 作品詳細画面への評価分布表示 | 評価ごとの件数・割合を作品詳細画面に表示する |
| お問い合わせフォーム | ゲスト・会員が運営者へ問い合わせをメール送信する |
| 利用規約の表示 | 利用規約をアプリ上で確認できるようにする |
| プライバシーポリシーの表示 | プライバシーポリシーをアプリ上で確認できるようにする |
| 会員登録時の同意確認 | 会員登録時に必要な同意・確認を行う。具体的な確認項目は実装Issueで決定する |

#### 管理者機能

| 機能・項目 | 概要 |
|---|---|
| 登録済み作品一覧 | 管理者が登録済み作品を一覧で確認する。具体的な表示項目は後続設計で決定する |

管理者画面は一人運営に必要な最小限とし、既存のLaravel Breeze認証と `users.role` による管理者認可を使用する。登録済み作品一覧などの管理機能は段階的に対応する。

#### TMDB連携

| 機能・項目 | 概要 |
|---|---|
| TMDB利用条件・クレジット対応 | attribution、notice、approved logo、branding、データ・画像の利用条件等を公式情報に基づいて確認・反映する（Issue 98） |
| TMDB後続機能のAPI技術調査 | 作品登録など、後続機能に必要な取得・変換・検証・エラー処理を実装前に調査する |
| 登録前モーダルのフロント入力検証・エラー表示 | タイトル・概要・カテゴリーについて、DB詳細設計で確定した入力契約に基づく検証、入力欄直下のエラー表示、`aria-invalid`・`aria-describedby`等の関連付けを整備する。Issue 230には含めず、独立Issueへの分割を検討中（Issue番号未確定） |
| カテゴリーマスタ初期データ・DB連携 | 既存「未定義」を維持して12カテゴリーをSeederへ追加する。新規登録候補は正式12件に限定し、実際の`categories.id`と接続する。「未定義」は新規登録時に選択・保存させない（現行Issue 228。DB設計・マイグレーション・SeederのIssue分割を検討中） |
| 1作品ずつの登録 | モーダルで編集したタイトル・概要全文と選択カテゴリー等を検証し、管理者専用API経由で作品を1件ずつDBへ保存する（Issue 228） |
| 重複登録防止 | 同じTMDB作品の重複登録を、サーバー側の検証とDBの一意性制約で防ぐ（Issue 228） |

TMDB検索・ジャンル取得・カード表示改善（Issue 212・231・232）は`develop`統合済み、**作品登録前モーダルUI（Issue 230）は作業ブランチで実装済み・PR前**、カテゴリーDB連携・作品登録API・DB保存（現行Issue 228）は未実装と区別する。フロント入力検証、DB詳細設計、マイグレーション／Seederについては後続Issueへの分割を検討中で、Issue番号は未確定。検索候補の拡張・ページネーションはIssue 227で別途扱う。

完成時の最小フローは「TMDB検索 → 検索結果一覧 → 登録前モーダルで内容確認・タイトルと概要編集・カテゴリーを1件選択 → 登録APIでDBへ1作品保存」とする。**現時点ではモーダルまでを作業ブランチで実装済み**で、登録ボタンは無効、入力のフロント検証・登録API・DB登録は未実装である。

アプリ独自カテゴリーは12種類から手動で単一選択し、TMDBの複数ジャンルから自動選択・変換しない。「その他」は選択可能だが、既存DB互換用の「未定義」は新規作品登録UIに表示しない。カテゴリーの正式名称・順序は[DB設計](DATABASE.md)、モーダル・検索JSONの仕様は[TMDB映画検索技術設計](TMDB_SEARCH_DESIGN.md)を正本とする。

登録APIのHTTPメソッド・URL・入力／応答契約、DB保存項目、`tmdb_id`の型・一意性制約、ポスター等の保存条件は、現行Issue 228の設計内容と関連する一次情報を確認して確定する。DB設計・DB実装・フロント入力検証のIssue分割は検討段階であり、未作成のIssue番号や未実装の仕様を確定済みと記載しない。
